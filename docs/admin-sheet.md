# 관리자 Google 계정

관리자 명단은 BOOONG 서버 전용 환경변수 `BOOONG_ADMIN_EMAILS`로 관리합니다. Google 이메일을 쉼표로 구분합니다.

```dotenv
BOOONG_ADMIN_EMAILS=operator@example.com,second@example.com
```

공백과 대소문자 차이는 무시하며 빈 항목과 중복은 제거합니다. 변수가 없거나 명단이 비었거나 이메일 형식이 잘못된 항목이 하나라도 있으면 관리자 API는 `503 admin_not_configured`로 접근을 차단합니다. 정상 명단에 없는 Google 계정은 `403 access_denied`입니다. 시트·프로필·브라우저 저장값으로 권한을 부여하거나 대체하지 않습니다.

## 설정과 변경

- 로컬: Git에서 제외된 `.env.local`에 설정하고 `npm run serve`로 서버를 시작합니다. 환경변수를 바꾸면 서버를 다시 시작합니다. 기존 로컬 전용 로그인 생략 동작은 그대로 유지되므로 실제 권한 검증은 로그인 생략이 없는 환경에서 확인합니다.
- 운영: 기존 BOOONG Vercel 프로젝트(`prj_P9RTgl9Az53r5VZ8i0diwW7YcJCH`, `booong.vercel.app`)의 서버 환경변수로 설정하고 재배포합니다. Preview도 사용할 경우 필요한 환경에 별도로 설정합니다. 다른 앱의 환경변수는 변경하지 않습니다.
- 추가·회수: 해당 환경의 명단에 이메일을 추가하거나 삭제한 뒤 재배포합니다. 서버는 각 요청에서 현재 프로세스의 명단을 읽으며 별도 명단 캐시를 사용하지 않습니다. 기존 배포에는 이전 설정이 남을 수 있으므로 권한 회수 시 예전 배포 URL의 접근도 확인합니다.
- 값은 서버에만 보관합니다. `NEXT_PUBLIC_`·`VITE_` 같은 공개 접두어, 브라우저 JS, 공개 JSON, Git에 넣지 않습니다.

## 기존 시트에서 전환

1. 기존 멤버 프로필 시트(`gid=1259304881`)의 `admin` 열에 있던 관리자 이메일을 확인해 서버 환경변수로 옮깁니다.
2. 환경변수와 새 코드를 배포한 뒤 기존 관리자 로그인, 비관리자 거부를 확인합니다.
3. 운영 접근 확인 후 공개 시트에서 `admin` 열을 삭제합니다. 새 코드는 이 열을 읽지 않습니다.

Google 로그인은 기존 BOOONG Firebase 웹 앱(`1:266288546185:web:727060b22ce9643d0c2158`, 프로젝트 `yadoran-2025`)을 사용합니다. 서버는 Firebase ID 토큰의 서명·발급자·대상 프로젝트·만료·Google 로그인 여부·이메일 인증을 검증한 뒤 `BOOONG_ADMIN_EMAILS` 명단과 대조합니다. 도름스 댓글 로그인은 기존 흐름을 유지합니다.

Firebase Authentication의 Google 제공자가 활성화되어 있어야 하고 이 앱의 서비스 도메인만 Authorized domains에 등록되어 있어야 합니다. 2026-10-01 재확인 기준 Google 제공자와 `booong.vercel.app` 승인 도메인이 설정되어 있습니다. 다른 앱의 인증 설정이나 도메인은 변경하지 않습니다.

관리자 메뉴, 방문 통계, 교과서 분석은 진입 시 권한을 확인합니다. 같은 화면에서의 관리자 확인 결과는 계정별로 최대 30초간 재사용하며 재확인 중 기존 화면을 유지합니다. 교과서 진입은 보호된 카탈로그 요청으로 권한 확인을 함께 처리하고, 카탈로그·PDF 요청마다 서버에서 Google 토큰을 검증합니다. 이 변경은 화면 접근을 제한하며 기존 Firebase 통계 원본의 공개 읽기 규칙은 유지됩니다.
