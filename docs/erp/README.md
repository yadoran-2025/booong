# 연구소 ERP

운영자 공간 → 연구소 운영 → 연구소 ERP (`research-erp.html`). 기존 Google 운영자 인증을 재사용한다. 기본 저장 경로는 비공개 Google Sheets 원장이며, 연결 승인 및 설정 전에는 조회·저장을 잠근다. 기존 Supabase 경로는 `RESEARCH_ERP_STORAGE=supabase`로 명시했을 때만 사용한다. 서버의 운영자 명단에 있는 모든 계정이 같은 연구소 장부를 본다. 모든 조회·등록·수정은 `/api/research-erp`에서 권한을 검사하며 공개 조회는 없다.

## 사용

- 실제 입출금이 끝난 거래를 날짜·분류·양의 원화 정수·내용으로 기록한다. 거래처·메모는 선택이다. 수입·지출을 나눈 분류 목록과 6종 빠른 입력 버튼을 제공하고 금액의 쉼표 입력을 허용한다. 미래 예정 거래나 반복 임차료를 자동 등록하지 않는다.
- 매출을 기본 입금 분류로 사용한다. 차입금·운영자 입금 등은 `매출 외 입금`으로 분리한다. 비용은 커피, 사료(밥), 연구소 임차료, 기타 비용이다.
- 월별 매출, 비용, 매출−비용, 입출금 차액을 표시한다. 입출금 차액 = 매출 + 매출 외 입금 − 비용. 기초 잔액을 관리하지 않으므로 통장 잔액이 아니다. 현금 기록 기준이며 세무 신고·발생주의 회계·자산/부채 관리를 대체하지 않는다.
- 수입·지출·분류·내용·거래처로 목록을 좁혀도 요약은 선택 월 전체를 기준으로 한다. 한국 시간 기준 오늘 날짜를 사용하고 거래일은 시간대 변환 없이 저장한다.
- 수정 가능. 취소하면 합계에서 제외하고 데이터를 보존한다. 취소 내역 포함을 켜서 복원할 수 있다. 취소 거래는 복원 후 수정한다.
- 같은 날짜·분류·금액·내용은 확인을 거쳐 추가한다. 생성 ID를 저장 재시도에 재사용하여 응답 유실 시 중복 등록을 막는다. 동시 수정은 revision으로 감지한다. 충돌 시 내용을 보관하고 새로고침한다.
- CSV는 선택 월 전체와 취소 거래를 포함하며 검색·분류 필터와 무관하다. UTF-8 BOM 및 수식 주입 방어를 적용한다. 계정 변경 시 표시 중인 금융 데이터와 입력을 비우고 조작을 잠근다.
- 월 최대 5,000건을 페이지로 모두 조회한다. 초과 시 합계를 보여주지 않고 오류를 표시한다. 원화 정수 합계는 이 한도에서 JS 안전 정수 범위 내다. 조회 도중 다른 운영자의 대량 변경이 있었다면 다시 불러와 확인한다.

## 기존 Supabase 경로 (선택)

새 시트 연결과 자동 병합하지 않는다. 기존 DB의 데이터는 그대로 보존하며, 데이터 이동은 별도로 검토한다.

### 활성화 전

이 작업은 배포 및 원격 DB를 변경하지 않는다. `setup.sql`을 검토하고 기존 BOOONG Supabase 프로젝트에 한 번 적용한 뒤 앱을 배포한다. 이 파일은 초기 설치 SQL이며, 기존 설치에 반복 적용하거나 기존 테이블을 삭제해 적용하지 않는다. 새로운 두 테이블과 인덱스·트리거만 만든다. 기존 공지·붕모 데이터는 사용하지 않는다.

RLS를 활성화하고 anon/authenticated/PUBLIC 권한을 회수한다. 별도 공개 정책은 없으며 서버 역할만 거래 조회·등록·수정이 가능하다. 행 삭제 권한은 부여하지 않는다. 감사 이력은 트리거가 같은 트랜잭션에서 작성하고 서버 역할에는 조회·등록만 부여한다. 서버가 검증한 운영자 이메일과 변경 전후 값이 남는다. Supabase 서비스 역할은 RLS를 우회하므로 키는 서버에만 보관한다.

설치 후 테이블 RLS·권한과 감사 트리거를 확인하고 테스트 거래로 등록→수정→취소→복원, 미인증 401/일반 사용자 403, anon 직접 접근 차단을 확인한다. 실제 거래는 자동 입력하지 않는다. 신규 테이블이 없거나 서버 설정이 없으면 화면은 조회 오류를 표시하고 저장을 잠근다.

검증: `node scripts/test-research-erp.mjs`, `npm run check`, `npm test`, `npm run smoke`. `scripts/test-research-erp-schema.mjs`는 `PGLITE_MODULE`로 지정한 PGlite의 로컬 임시 DB에서 설치 SQL과 권한·감사 이력을 검증한다. `scripts/test-research-erp-browser.mjs`는 `PLAYWRIGHT_MODULE`을 지정하고 로컬 서버를 실행한 뒤 사용한다. 브라우저 테스트는 인증 모듈과 ERP API를 테스트 탭에서만 대체하며 실제 로그인/DB에 접근하지 않는다.


## Google Sheets 직접 연결 — 기존 서비스 계정

대상은 `1ZQvVTUhDZPrizJvkKiFAPz_jI1o0NRkEWAijGHVdd2U` 한 파일이다. 서버가 기존 `FIREBASE_BUNGMO_SERVER`의 `booong-bungmo-server@yadoran-2025.iam.gserviceaccount.com` 키를 재사용한다. 새 장기 키, 사용자 계정 전체 Sheets 동의, Apps Script 프로젝트·웹앱·HMAC 키는 필요하지 않다.

사용자가 승인한 권한은 이 파일 하나를 위 서비스 계정에 **편집자(writer)**로 공유하는 것이다. Google 파일 권한은 워크북 전체에 적용되며 탭/셀별 OAuth 권한은 아니다. 서비스 계정의 OAuth access token은 `https://www.googleapis.com/auth/spreadsheets`만 요청하고 개인 사용자를 대리하는 `sub`는 넣지 않는다. 접근 가능한 파일은 서비스 계정 자체의 파일 ACL에 의해 제한된다. 서버 코드는 파일 ID·원장 `77402507`·변경이력 `297913949`를 고정한다. 분류·설정·스키마 안내 탭은 수정하지 않는다.

```text
RESEARCH_ERP_STORAGE=google_sheets
FIREBASE_BUNGMO_SERVER=<이미 사용하는 서버 전용 Secret>
```

`google_sheets`는 기본 저장 경로다. 기존 Supabase를 계속 쓸 때만 `RESEARCH_ERP_STORAGE=supabase`를 명시한다. 저장소 간 자동 병합·대체 저장은 하지 않는다. 이전 Apps Script URL/비밀키 환경변수는 사용하지 않는다. 키가 없거나 다른 계정/프로젝트의 키면 `sheets_not_configured`로 잠근다. Google의 API 비활성화·파일 접근 거부·통신 장애는 실패로 처리하며 원격 설정을 자동 변경하지 않는다.

### 인증과 비밀값

기존 Firebase Google 신원과 운영자 명단을 `/api/research-erp`에서 검증한다. 등록·수정에는 Origin도 검사한다. 수정자와 시각은 서버가 정하며 클라이언트 값을 신뢰하지 않는다. Google OAuth access token은 기존 키로 발급해 서버 메모리에서만 만료 60초 전까지 캐시한다. 키·JWT assertion·access token·실제 거래 내용을 브라우저·URL·로그에 출력하지 않는다. Google 호출은 고정 HTTPS 주소만 사용하고 리디렉션을 거부한다.

Vercel에서는 기존 `FIREBASE_BUNGMO_SERVER`를 서버 전용 Secret으로 유지한다. 공개 prefix나 프런트엔드 번들에 넣지 않는다. 운영 키를 쓰는 Preview/Development로 파일 접근을 넓히지 않는다. 현재 운영 Secret 설정이 이미 있는지 확인한 뒤 필요한 설정만 별도 허가하에 적용한다. 이번 작업은 배포하지 않는다.

운영자 명단은 메인 대시보드 워크북의 `멤버 프로필` CSV에서 읽는다. 이 파일은 현재 `anyone:writer` 공유가 확인되었으므로 금융 데이터 운영 전에 운영자 명단 열의 보호 및 편집 권한을 검토해야 한다. 보호 범위는 아직 확인하지 않았다. 이 작업에서 다른 시트 권한은 변경하지 않는다.

### 동시 처리와 데이터 보존

모든 ERP 조회·저장은 원장 파일의 developer metadata ID `198614320`, key `booong_erp_writer_v1`을 잠금으로 사용한다. Google은 metadata ID를 파일 안에서 고유하게 유지하므로 서로 다른 서버 인스턴스도 같은 ID를 동시에 만들 수 없다. 잠금 값은 요청 UUID와 시작 시각이며 비밀키가 아니다. 새 외부 저장소·자격증명·테이블은 만들지 않는다.

1. 잠금을 획득한 뒤 원장과 이력 헤더를 검사하고 전체 원장(헤더 포함 최대 50,000행)을 읽는다. 다른 요청의 잠금이 있으면 `ledger_busy`로 실패한다. 잠금 생성 응답이 유실되면 메타데이터 값을 조회해 자신의 잠금임을 확인한 경우에만 진행한다.
2. ID 없이 `voided=false`만 있는 예약 행은 제외한다. 다른 값이 있는 ID 없는 행, 중복 ID, 잘못된 날짜·분류·금액·헤더는 오류로 처리하여 합계 누락을 방지한다. 날짜는 ISO `YYYY-MM-DD`와 Sheets 날짜 정수 셀을 읽고 시각은 ISO 8601 문자열로 저장한다.
3. 원장 행, 변경이력, **자기 잠금 해제**를 한 번의 atomic `spreadsheets.batchUpdate`로 처리한다. 실패하면 거래와 이력이 부분 반영되지 않는다. 값만 수정해 서식·다른 열·탭은 보존한다. 문자열은 `stringValue`로 써서 수식으로 실행하지 않는다.
4. 거래 ID는 소문자로 정규화한다. 같은 ID·내용·수정자의 생성 재시도는 기존 거래를 반환하고 새 이력을 만들지 않는다. 수정은 revision이 다르면 409다. 취소/복원은 행 삭제 없이 전후 JSON을 이력에 남긴다.
5. 월별 5,000건(취소 포함)을 완전 조회한다. 5,000건이 찬 월로 새 거래 등록·이동을 막는다. 예약 행을 먼저 쓰고 부족할 때 한 행을 추가한다.

**결과가 불확실한 쓰기에는 잠금을 자동 해제하거나 시간만 보고 빼앗지 않는다.** 늦게 도착한 기존 쓰기가 새 거래를 덮어쓰는 것을 막기 위해서다. 성공한 쓰기는 원장·이력·잠금 해제가 함께 반영되므로 응답 유실 뒤 생성 재시도도 안전하다. Google이 쓰기를 확정 거절한 400/401/403/404 응답이거나 쓰기를 보내기 전 오류일 때만 자기 잠금을 별도로 해제한다. 조회/중복 확인 후에도 자기 잠금만 해제한다.

서버 중단이나 결과 불확실한 실패로 잠금이 남으면 화면이 조회·저장을 잠근다. 자동 복구하지 않으며 운영자가 기록을 확인해야 한다. 복구는 다음 절차로 별도 수행한다.

- 모든 ERP 인스턴스의 쓰기를 중지하고 진행 중 Google 요청이 종료된 것을 확인한다. 단순 경과 시간만으로 잠금을 삭제하지 않는다.
- metadata ID·key·요청 소유값, 거래 ID·revision·변경이력을 읽어 반영 결과를 확인한다. 원장과 이력이 맞지 않으면 먼저 원인을 조사한다.
- 종료된 요청의 잠금임이 확인된 경우에만 ID+key+해당 소유값을 모두 조건으로 그 잠금을 삭제한다. 다른 메타데이터·셀·행은 삭제하지 않는다. 이 복구는 명시적인 운영자 조작이며 앱에서 자동 실행하지 않는다.

잠금은 이 ERP를 통한 요청끼리 적용된다. 시트 직접 편집·다른 앱의 쓰기는 보호하지 못하므로 운영 중 등록·수정은 ERP로 한다. 서비스 계정의 기존 다른 파일 접근 권한이나 Cloud IAM 역할은 이 코드가 바꾸지 않는다.

### 검증

- `node scripts/test-research-erp-sheets.mjs`: Google/OAuth를 메모리로 대체한다. 기존 계정/범위/파일 고정, 토큰 캐시, 운영자 인증·Origin, 날짜·예약 행, 월 5,000건, 원장/이력/잠금 원자성, 서로 다른 모듈 인스턴스 간 잠금, revision 충돌, 응답 유실 재시도, 불확실한 쓰기의 잠금 유지, 취소/복원·수식 문자열·잘못된 응답을 검사한다. 테스트 키는 프로세스 메모리에만 있으며 실제 서비스는 호출하지 않는다.
- `node scripts/test-research-erp.mjs`: 기존 Supabase 경로 회귀 검증.
- `PLAYWRIGHT_MODULE=<playwright/index.mjs> node scripts/test-research-erp-browser.mjs`: 로컬 서버 `127.0.0.1:8789`, 인증/API를 테스트 탭에만 대체해 PC/모바일 등록·필터·실패·재시도를 검사한다.
- `ERP_LIVE_VERIFY=1 node --env-file=.env.local scripts/verify-research-erp-live.mjs`: 승인된 계정/파일만 사용한다. 실제 셀 값을 해시 비교하고 메타데이터 잠금 획득·경합 차단·해제를 검증한다. fetch 보호막이 실제 셀 쓰기를 거부한다. 실원장에 테스트 거래를 추가하지 않는다. 원문 키·토큰·거래값은 출력하거나 저장하지 않는다.
- `npm run check`, `npm test`, `npm run smoke`: 구문·import·기존 기능·로컬 페이지 회귀 검증.


### 2026-11-04 실제 연결 확인 결과

승인된 ERP 파일에 기존 서비스 계정의 `writer` 권한이 추가되었고 Drive 메타데이터로 소유자 1명 + 해당 서비스 계정 1명임을 확인했다. 기존 키의 Google OAuth 인증, Sheets API 사용, 원장 조회(선택 월 거래 0건), 실제 고유 metadata ID의 경합 차단·해제가 성공했다. 셀 쓰기를 차단하는 검증으로 모든 탭의 셀 값·시트 크기·metadata 전후 해시가 일치했다. 테스트 거래는 실제 파일에 쓰지 않았다.

단위/회귀 전체 테스트, 구문·import 137개 파일, 15페이지 smoke, PC·모바일 브라우저 검증을 통과했다. 새 장기 키·환경변수·별도 Apps Script·다른 시트 권한·배포는 변경하지 않았다. 운영 Vercel Secret 및 운영자 명단 보호 범위는 아직 확인되지 않았으며 배포 허가 후 운영 활성화 전에 확인한다.
