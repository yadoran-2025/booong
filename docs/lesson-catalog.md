# 수업 관리

운영자 공간 → **수업 관리**에서 기존 구글 시트를 처음 한 번 가져옵니다. 수업·단원 시트를 함께 가져오며 비공개 수업, 기존 수업 ID와 추가 열도 보존합니다. 기존 시트를 변경하거나 삭제하지 않습니다.

가져온 뒤에는 관리자 화면이 수업 목록의 원본입니다. 시트의 수정 사항을 자동으로 덮어씌우거나 재가져오지 않습니다. 제목·소개·제작자·분야·자료 링크·과목과 단원·수업/게임·공개 여부·신규 표시를 수정할 수 있습니다. 새 수업은 비공개로 시작합니다. 삭제 대신 비공개로 보관합니다. 수업 ID는 수정할 수 없으며, 제목이나 단원이 바뀌어도 저장·댓글·조회수·썸네일 연결을 유지합니다.

과목을 선택하고 단원을 복수 선택할 수 있습니다. 다른 과목으로 이동해도 선택한 단원은 유지됩니다. **썸네일 수정**은 해당 수업의 기존 이미지 편집기를 바로 엽니다. 비공개 수업의 이미지도 준비할 수 있습니다.

배포 환경에서는 기존 private Vercel Blob에 `booong-lessons/catalog.json`을 저장합니다. 별도 DB나 Firebase 리소스를 추가하지 않습니다. 조건부 쓰기(ETag)와 목록 수정 버전으로 동시 덮어쓰기를 방지합니다. 충돌하면 입력 내용을 유지하므로 필요한 내용을 복사한 뒤 새로고침합니다. 전체 목록 하나를 갱신하는 구조이므로 동시 편집이 잦아지면 수업별 저장소로 전환합니다. 최대 5,000개 수업·8MB 목록을 허용합니다.

공개 API `/api/lesson-catalog`는 공개 수업만 반환하며 CDN·서버에 각각 30초 캐시합니다. 수정 반영은 약 1분 걸릴 수 있습니다. 관리자 API는 Google 운영자 인증을 확인하며 캐시하지 않습니다. 저장은 같은 출처의 JSON 요청만 받습니다. 공개 API는 불필요한 쿼리를 거절하고 동시 읽기를 합치며, 장애 시 10초 동안 재요청을 줄입니다. 앱 요청 제한은 인스턴스별 IP당 분당 600회입니다. 운영 배포 시 기존 썸네일 WAF 규칙에 `/api/lesson-catalog`와 `/api/admin?catalog=1`을 함께 포함해야 합니다.

최초 가져오기 전에는 기존 시트를 계속 사용합니다. 수업 관리 전환 뒤에는 홈페이지가 공개 API를 우선 사용합니다. 구글 시트는 초기 수업·단원 가져오기와 기존 운영자 명단 확인에 사용됩니다.

저장소 연결이 실패하면 이미 확인한 관리자 목록의 공개 캐시만 재사용합니다. 캐시가 없으면 재시도 안내를 표시하며, 예전 시트의 공개 상태로 돌아가 숨긴 수업을 다시 표시하지 않습니다.

로컬 서버는 `.data/lesson-catalog/catalog.json`에 별도로 저장하며, 이 데이터는 Git이나 배포에 포함하지 않습니다. 운영 사이트에서도 최초 가져오기를 실행해야 합니다.

검증: `node scripts/test-lesson-catalog.mjs`, `npm test`, `npm run check`, `npm run smoke`.
