# 수업 관리

운영자 공간 → **수업 관리**에서 기존 구글 시트를 처음 한 번 가져옵니다. 수업·단원 시트를 함께 가져오며 비공개 수업, 기존 수업 ID와 추가 열도 보존합니다. 기존 시트를 변경하거나 삭제하지 않습니다.

수업은 카드 목록으로 표시합니다. 카드의 **수정**을 누르면 기존 정보를 채운 편집 모달이 열립니다. **수업 등록**도 같은 모달에서 작성합니다. 저장이 완료되면 모달이 닫히고 목록에 반영되며 검색·필터는 유지됩니다. 닫기·취소·Esc로 닫을 때 저장 전 수정 내용이 있으면 버릴지 확인합니다. 새 수업은 비공개로 추가되며, 카드에서 다시 수정하여 썸네일을 추가할 수 있습니다.

카드는 큰 썸네일 아래 제목·과목·선택한 단원명과 프로필 제작자 이름 칩을 보여줍니다. 단원명은 현재 선택한 단원 코드를 기준으로 읽고 같은 이름은 중복 표시하지 않습니다. 소개와 자료 링크는 편집 모달에서 확인합니다. 공개 여부 버튼과 과목·제작자 목록, **신규만**을 조합해 필터링합니다. 과목은 학교급별로 묶고 미지정 과목·제작자도 선택할 수 있습니다. 검색은 제목·소개·과목·단원·제작자 코드와 이름·맡은 일을 대상으로 하며 공백으로 나눈 검색어를 모두 포함하는 수업을 찾습니다. 결과 개수와 **필터 초기화**를 표시하고 저장·새로고침 후에도 검색과 필터를 유지합니다.

가져온 뒤에는 관리자 화면이 수업 목록의 원본입니다. 시트의 수정 사항을 자동으로 덮어씌우거나 재가져오지 않습니다. 제목·소개·제작자·자료 링크·과목과 단원을 수정할 수 있습니다. 새 수업은 비공개로 시작합니다. 목록에 남겨둘 수업은 비공개로 보관합니다. 기존 수업은 편집 모달의 **수업 삭제**에서 제목과 복구 불가 안내를 확인한 뒤 삭제할 수 있습니다. 삭제가 완료되면 운영자·공개 목록에서 제거됩니다. 썸네일·댓글 등 별도 저장소는 함께 삭제하지 않습니다. 저장과 같은 관리자 권한·목록 수정 버전·ETag 검사를 적용하며, 충돌이나 연결 실패 시 편집 내용을 유지합니다. 수업 ID는 수정할 수 없으며, 제목이나 단원이 바뀌어도 저장·댓글·조회수·썸네일 연결을 유지합니다.

수업 소개·교사용 자료·도름스 링크는 각각 한 줄 전체에 입력합니다. 저장이 끝나면 화면 하단에 완료 알림이 표시됩니다. 실패 시에는 오류 알림을 표시하고 입력을 유지합니다.

카드의 **공개·신규 체크박스**는 체크 즉시 각각 저장합니다. 과목·단원이 저장되지 않은 수업은 먼저 편집 화면에서 단원을 저장한 뒤 공개합니다. 표시 설정은 해당 필드만 수정하며, 충돌·실패 시 체크를 원래대로 되돌리고 오류를 표시합니다. 편집 화면의 자료 유형 선택은 없앴습니다.

과목 버튼을 누르면 대단원별로 단원을 펼쳐 보여주는 모달이 열립니다. 단원을 복수 선택하고 **선택 적용**을 누르면 편집 화면의 단원 칩에 반영됩니다. 취소·닫기·Esc는 모달에서 바꾼 선택을 버립니다. 다른 과목의 선택은 유지되며, 선택한 단원이 있는 과목 버튼이 강조됩니다. 최종 변경은 수업의 **저장**으로 반영합니다. 수업 등록 모달에서도 같은 단원 선택을 사용합니다.

개별 수업의 **썸네일 → 이미지 수정**에서 파일 선택·드래그·붙여넣기와 자유로운 확대·축소·위치 조절을 할 수 있습니다. 같은 비율의 이미지도 이동할 수 있으며, 프레임 바깥 영역은 흰색 여백으로 저장합니다. **전체 보기**는 이미지가 잘리지 않게 맞추고 **꽉 채우기**는 프레임을 채웁니다. 드래그와 마우스 휠 또는 키보드로 조작하는 확대·가로·세로 막대를 사용합니다. 이미 저장된 썸네일에 잘린 부분은 원본 파일을 다시 선택해야 조절할 수 있습니다. **썸네일 저장**은 이미지를 저장하며, 작성 중인 수업 정보는 유지됩니다. **이전 이미지로 복원**도 수업 화면에서 바로 할 수 있습니다. 비공개 수업의 이미지도 준비할 수 있으며, 새 수업은 먼저 저장한 뒤 이미지를 추가합니다.

**제작자 · 맡은 일**에서 기존 회원 코드 칩을 복수 선택하고 사람마다 한 일을 입력합니다. 회원 이름도 함께 표시합니다. 기존 제작자는 미리 선택되며 역할은 추정해서 채우지 않습니다. `contributors`에 코드·역할을 저장하고 기존 `maker` 문자열도 코드 목록으로 유지해 회원별 제작 자료 연결을 보존합니다. 수업 소개에는 코드와 입력한 역할이 함께 표시됩니다. 등록되지 않은 기존 코드도 보존합니다.

배포 환경에서는 Firebase 프로젝트 `yadoran-2025`의 BOOONG 전용 Realtime Database `yadoran-2025-booong-content`에 `content/catalog`을 저장합니다. 서버 전용 `FIREBASE_BOOONG_CONTENT_SERVER` 계정만 접근하며 다른 앱의 DB와 규칙은 사용하지 않습니다. JSON 문자열로 원래 열·빈 배열·순서를 보존합니다. 조건부 쓰기(ETag)와 목록 수정 버전으로 동시 덮어쓰기를 방지합니다. 충돌하면 입력 내용을 유지하므로 필요한 내용을 복사한 뒤 새로고침합니다. 전체 목록 하나를 갱신하는 구조이므로 동시 편집이 잦아지면 수업별 저장소로 전환합니다. 최대 5,000개 수업·8MB 목록을 허용합니다.

공개 API `/api/lesson-catalog`는 공개 수업만 반환합니다. 수업·썸네일 목록은 Vercel CDN에 각각 1시간 캐시하며, 관리자가 저장하면 해당 목록의 태그만 즉시 삭제해 다음 조회에서 최신 내용을 읽습니다. 브라우저에는 오래 보관하지 않습니다. CDN이 원본을 요청할 때는 다른 서버의 오래된 메모리 목록을 재사용하지 않고 Firebase에서 읽으며, 동시에 들어온 요청은 합칩니다. 관리자 API·저장 응답·오류는 캐시하지 않습니다. 캐시 삭제가 실패해도 저장 결과는 보존하고 관리자에게 최대 1시간의 갱신 지연을 알립니다. 썸네일 이미지 자체는 기존처럼 고유 URL로 1년 캐시합니다. 캐시를 위한 별도 Runtime Cache나 DB는 추가하지 않습니다.

저장은 같은 출처의 인증된 요청만 받습니다. 공개 API는 불필요한 쿼리를 거절하며, 장애 시 10초 동안 재요청을 줄입니다. 앱 요청 제한은 인스턴스별 IP당 분당 600회입니다. 로컬 목록의 메모리 캐시는 30초이고 저장 시 지우며, 로컬 저장으로 운영 사이트 캐시를 삭제하지 않습니다. 운영 배포 시 기존 썸네일 WAF 규칙에 `/api/lesson-catalog`와 `/api/admin?catalog=1`을 함께 포함해야 합니다.

최초 가져오기 전에는 기존 시트를 계속 사용합니다. 수업 관리 전환 뒤에는 홈페이지가 공개 API를 우선 사용합니다. 구글 시트는 초기 수업·단원 가져오기에 사용됩니다. 운영자 명단은 서버 전용 `BOOONG_ADMIN_EMAILS`로 관리합니다.

저장소 연결이 실패하면 이미 확인한 관리자 목록의 공개 캐시만 재사용합니다. 캐시가 없으면 재시도 안내를 표시하며, 예전 시트의 공개 상태로 돌아가 숨긴 수업을 다시 표시하지 않습니다.

로컬 서버는 `.data/lesson-catalog/catalog.json`에 별도로 저장하며, 이 데이터는 Git이나 배포에 포함하지 않습니다. 운영 사이트에서도 최초 가져오기를 실행해야 합니다.

검증: `node scripts/test-lesson-catalog.mjs`, `npm test`, `npm run check`, `npm run smoke`.

Blob 원본은 백업으로 보존합니다. 이전 범위·검증·복구 절차는 [BOOONG 콘텐츠 이전](booong-content-migration.md)을 따릅니다.
