# 공지 관리

관리자 화면의 **공지 관리**에서 제목(최대 120자), 내용(최대 5,000자), 선택 링크(http/https)를 입력합니다. 등록하면 바로 게시됩니다. 수정, 내리기, 다시 게시하기를 지원합니다. 공지를 내리는 작업은 데이터를 삭제하지 않습니다.

공개된 공지는 수업 목록의 검색창 아래, 과목 선택 위에 최신 등록순으로 표시됩니다. 여러 공지가 있으면 4초마다 위로 넘어갑니다. 마우스나 키보드로 접근 중이거나 대화상자가 열린 동안에는 멈추며, 사용자가 멈춤/재생을 선택할 수 있습니다. 기기의 동작 줄이기 설정에서는 자동 재생을 시작하지 않습니다. 공지가 없으면 공지 바를 표시하지 않습니다. 제목을 누르면 본문을 읽고 관련 링크를 열 수 있습니다.

기존 BOOONG Supabase 프로젝트 `swyiidgsbbxzshjlkeue`의 `public.booong_notices` 테이블만 사용합니다. 기존 `SUPABASE_URL`, `SUPABASE_SECRET_KEY` 서버 설정을 재사용합니다. 브라우저에는 키를 전달하지 않습니다. 테이블은 RLS가 켜져 있으며 익명 및 일반 인증 역할의 직접 접근은 허용하지 않습니다. 서버 역할에는 조회·등록·수정만 허용합니다.

`GET /api/notices`는 게시된 공지만 공개합니다. `GET /api/notices?admin=1`, `POST`, `PATCH`는 기존 Google 관리자 인증과 멤버 시트의 관리자 명단으로 권한을 검증합니다. 변경 요청의 출처를 확인하고 제목·내용·링크를 검증합니다. 같은 공지에 대한 동시 수정은 `updated_at` 조건으로 충돌을 감지하며, 저장 실패 시 관리자 입력을 지우지 않습니다.

Firebase 웹 앱 `1:266288546185:web:727060b22ce9643d0c2158` / 프로젝트 `yadoran-2025`는 기존 관리자 인증에만 사용합니다. 이 기능은 Firebase 규칙·Functions·Hosting 설정이나 공유 데이터베이스를 변경하지 않습니다.

최신 100개 공지를 조회하며, 한 번 연 수업 목록에서는 읽은 결과를 재사용합니다. 새로 등록한 공지는 수업 목록을 새로 열거나 새로고침하면 표시됩니다. 누적 공지가 100개를 넘으면 보관 목록에 페이지 나누기를 추가합니다.
