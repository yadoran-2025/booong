# BOOONG 응답 속도와 Firebase 비용 점검

2026-11-07 운영 사이트를 측정했다. 수업·프로필의 반복 조회는 CDN 덕분에 빠르다. 눈에 띄는 병목은 전체 글꼴 선다운로드, 공지의 매번 원본 조회, 중복 수업 목록 요청, 사용하지 않는 스쿠터 대체 이미지였다. 이 네 부분을 개선했다. Firebase 규칙·IAM·다른 앱 설정과 교과서 파일은 변경하지 않았다.

## 측정과 개선

HTTP는 같은 환경에서 경로별 3~4회 측정했다. 브라우저는 새 Chrome 컨텍스트, 390×844 화면, 약 6Mbps 다운로드·80ms 지연·CPU 4배 감속 조건으로 첫 방문과 과목을 저장한 재방문을 확인했다. 실제 휴대폰 평균이나 사용자 전체의 Core Web Vitals 통계는 아니다. MB/GB는 십진 단위다.

| 항목 | 개선 전 | 확인한 개선 |
| --- | --- | --- |
| 수업 목록 API | CDN 적중 약 21~32ms, 첫 연결 포함 87ms | 기존 캐시 유지. 새 배포 원본 조회는 약 1.12초, 이후 적중 14~20ms |
| 구성원 API | CDN 적중 약 15~21ms, 첫 연결 포함 80ms | 기존 캐시 유지. 새 배포 원본 조회 약 0.48초, 이후 적중 15~31ms |
| 공지 API | 매번 원본 조회, 약 0.93~2.01초 | CDN 적중 14~18ms. 등록·수정·내리기·재게시 성공 후 해당 태그 갱신 |
| 첫 방문 글꼴 전송 | 약 2.06MB | 약 0.18MB, 약 91% 감소 |
| 재방문 화면 글꼴 전송 | 약 2.06MB | 약 0.31MB, 약 85% 감소 |
| 첫 방문 전체 전송 | 약 2.34MB | 약 0.47MB, 약 80% 감소 |
| 과목 저장 후 홈 전체 전송 | 약 4.38MB | 최종 배포 약 1.64MB, 약 63% 감소 |
| 첫 진입 수업 API 요청 | 재방문 화면에서 2회 | 1회. 로컬 목록과 관리 목록은 병렬 요청 |
| 숨겨진 스쿠터 대체 이미지 | 3D가 정상이어도 약 0.99MB 다운로드 | 3D 실패 때만 다운로드. 정상 3D와 실패 시 대체 이미지를 각각 검증 |

첫 방문의 첫 글자 표시(FCP)는 같은 조건의 단일 표본에서 1.35초→1.17초였다. 과목을 저장한 재방문 화면의 LCP는 개선 전 4.65초, 최종 운영 배포 3.91초였다. 최종 재방문 FCP는 1.88초로 이전 1.45초보다 늦었고, 중간 배포에서는 1.14초였다. 캐시·첫 연결 상태에 따라 변동하므로 FCP가 일관되게 개선됐다고 단정하지 않는다. 위의 전송량 감소와 캐시 적중을 더 확실한 개선 근거로 본다. 표본 수가 적어 실제 사용자 평균이나 보장 수치로 쓰지 않는다.

전체 글꼴을 미리 받던 6개 페이지(index, about, asset-search, worksheet-maker, select, author)는 같은 버전·같은 서체의 문자별 분할 CSS를 사용한다. 디자인 시스템 버전·색·크기·폰트 이름은 유지했다. 공지는 수업·프로필과 같은 최대 1시간 CDN 캐시를 사용한다. 관리자·오류·잘못된 쿼리는 캐시하지 않으며, 캐시 갱신 실패 시 저장 결과를 보존하고 관리자에게 갱신 지연을 알린다.

처음 원본을 읽는 요청은 여전히 느릴 수 있다. Vercel 함수는 `iad1`, 콘텐츠 DB는 싱가포르다. 기존 기본 DB는 미국에 있고 다른 API의 연결 대상도 달라, 전체 함수 지역을 일괄 변경하지 않았다. 3D 모듈과 배경 이미지도 남아 있으므로 저사양 기기의 재방문 화면은 추가 측정 여지가 있다.

## Firebase 실사용량

Cloud Monitoring 조회 창은 11월 1일 00:00 KST부터 11월 7일 측정 시점까지다. 콘텐츠 DB는 11월 7일 생성됐으므로 생성 이후 관측치이며 이전 검증 트래픽도 포함된다. 월말 사용량으로 환산하지 않았다.

| 자원 | 관측한 사용량 | 해석 |
| --- | --- | --- |
| BOOONG 콘텐츠 RTDB | 전송 약 0.89MB, 원본 JSON 합계 약 53.5KB | 현재 규모는 작다. CDN 적중 요청은 DB를 다시 읽지 않는다 |
| 기본 RTDB(BOOONG 통계) | 전송 약 8.13MB, 최대 저장 약 0.24MB | 현재 작지만 공개 원본 조회와 누적 이력 증가에 주의 |
| 왓챠 RTDB | 전송 약 24.55MB, 최대 저장 약 14.10MB | 현재 작다. 전체 책 목록·공유 스냅샷 재조회가 증가 경로이며 서버 내 1시간 책 목록 캐시가 있다 |
| 공유 프로젝트 Firestore 전체 | 읽기 1,447회, 쓰기 6회 | 붕모만의 수치로 분리할 수 없다. 현재 관측량은 낮다 |
| 기본 Storage 버킷 | 최대 저장 약 7.65GB, 전송 약 20.04MB | 저장과 외부 전송을 따로 봐야 한다 |

RTDB 전송 지표 `network/sent_bytes_count`는 암호화·프로토콜 부가량을 포함한다. 저장량 GAUGE는 날짜별 값을 합산하지 않고 최대값을 사용했다. 새 콘텐츠 DB의 일별 저장 지표는 아직 나타나지 않아 검증한 JSON 크기를 별도로 표기했다. 최종 청구서, 크레딧·세금·통화 적용과 결제 예산 알림은 조회하지 않았다.

현재 공식 가격표의 RTDB 무료 전송은 Blaze 기준 하루 360MB이며 이후 $1/GB, 무료 저장은 1GB 이후 $5/GB-month다. 무료 할당량은 앱별로 따로 주어지는 것이 아니라 프로젝트 단위로 공유된다. Firestore 표준 무료 문서 읽기는 하루 50,000회다. 관측한 DB 사용량 자체에서는 대량 과금 징후가 보이지 않는다. [Firebase 가격표](https://firebase.google.com/pricing), [RTDB 청구 설명](https://firebase.google.com/docs/database/usage/billing)

## 비용이 커질 수 있는 부분

**교과서 다운로드가 가장 큰 전송 위험이다.** 서울(`asia-northeast3`) 버킷의 `booong/textbooks/`에는 PDF 444개, 약 7.63GB가 있다. 원본 17개가 2.57GB, 대단원 106개가 2.54GB, 중단원 321개가 2.52GB다. 모든 경로가 현재 카탈로그의 원본 또는 수업 자료에서 참조돼, 사용하지 않는 파일로 판정한 것은 없다.

원본 중 최대 파일은 약 670MB, 중단원 자료에도 약 195MB 파일이 있다. 195MB 자료를 100번 전량 받으면 약 19.5GB가 된다. 뷰어에는 이미 범위 요청·요청 구간 재사용·자동 전체 다운로드 중지가 있으므로 단순 열람마다 전량을 받는 구조는 아니다. 전체 캡처·내보내기나 많은 자료를 반복해서 여는 경우를 주의해야 한다. 원본 보존과 파일 재최적화 가능성을 먼저 검토해야 하며 이번에는 삭제하거나 재압축하지 않았다.

이 버킷은 서울에 있어 Cloud Storage의 미국 일부 지역용 Always Free 혜택을 그대로 적용할 수 없다. 저장량이 적거나 다운로드 100GB 미만이라는 이유만으로 무료라고 판단하면 안 된다. 저장비 자체와 대량 외부 전송 비용은 구분해야 한다. [Google Cloud Storage 지역별 가격·무료 조건](https://cloud.google.com/storage/pricing)

**공개 통계 원본은 봇에 의한 반복 다운로드 위험이 있다.** 실제 익명 `analytics.json?shallow=true` 조회가 성공했고, 방문자·클릭 이력을 포함한 상위 경로가 공개 읽기 상태다. 일반 화면은 주로 집계 경로를 읽지만, 직접 원본을 반복 요청하는 경우에는 Vercel 캐시나 WAF를 거치지 않는다. 방문자 이력도 누적된다. 다음 비용·접근 개선의 우선순위는 원본 조회를 제한하고 집계만 캐시 API로 제공하는 설계다. 현재 추적·관리자 통계가 의존하는 경로라 이번 속도 수정에서 규칙을 임의로 바꾸지 않았다.

붕모의 실시간 Firestore 구독은 재접속과 초기 전체 조회 때 읽기가 늘 수 있다. 구독 해제 처리는 있으며 현재 관측량은 낮지만, 모임과 참가자가 많아지면 지난 모임 범위와 목록 개수를 제한하는 방식이 적절하다. [Firestore 실시간 구독 과금](https://firebase.google.com/docs/firestore/pricing)

## 검증과 기록

`npm test`, `npm run check`, `npm run smoke`가 통과했고 25개 페이지의 로컬 참조를 확인했다. 운영 API의 수업·프로필 응답도 이전 데이터와 일치한다. 운영 배포는 기존 운영 소스를 기준으로 이번 파일만 교체하며, 작업 폴더의 다른 변경은 포함하지 않는다. Firebase 규칙·데이터 이전·파일 삭제·결제 설정 변경은 하지 않는다.

최종 운영 배포는 `dpl_CKwg1kByUL4fauaxr5tZTNJvAhKg`이다. 점검 전 배포 `dpl_CTwunneQyyQo7DFwjB9crXksRhdq`와 비교하여 원본 529개 중 이번 작업의 12개 파일만 달라졌음을 확인했다. 정상 WebGL에서는 스쿠터 PNG 요청 0회, WebGL 실패에서는 이미지 요청 1회와 화면 표시를 확인했다. 운영 공지를 실제 등록·수정하는 검증은 하지 않았으며 해당 저장·캐시 갱신 경로는 테스트 환경에서 검증했다.

측정 원본과 배포 범위 기록은 Git·정적 내보내기에서 제외되는 `.data/performance-2026-11-07/`에 보관한다. `http-before.json`, `http-after.json`, `mobile-before.json`, `mobile-after.json`, `mobile-final.json`, `scooter-verification.json`, `cloud-monitoring.json`, `storage-monitoring.json`, `textbook-inventory.json`, `production-verification.json`을 확인할 수 있다. 브라우저 측정 방문은 소량의 통계 트래픽을 발생시켰다.
