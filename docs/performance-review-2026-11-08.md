# 사이트 성능 점검 · 2026-11-08

운영 사이트의 주요 문서 8개와 공개 API 4개를 읽고, 홈·소개·자료 검색·붕모 진입을 브라우저에서 확인했다. 쌀바구니의 기존 성능 회귀 테스트도 실행했다. 코드에서는 화면 초기화, 반복 조회, 숨긴 화면의 타이머, 실시간 구독 해제를 점검했다. 확인한 표본에서는 사이트 전체에 공통되는 지속적인 서버 장애는 없었지만, 홈의 불필요한 조회와 코드 로딩, 일부 미리보기 요청을 줄일 수 있었다.

## 함께 확인한 부분

- 문서 `/`, 소개, 자료 검색, 저작 도구, 활동지, 왓챠, 쌀바구니, 붕모 모두 HTTP 200이었다. 문서 응답 헤더까지 약 15~328ms인 단일 표본이다.
- 목록·프로필·공지 API의 CDN 적중 응답은 약 20~35ms였다. 통계 API의 캐시 미적중 응답은 약 478ms였다. 이 값만으로 사용자 평균이나 최대 지연을 판단할 수 없다.
- 자료 검색은 290개 자료 중 선택한 종류의 카드 50개를 표시했다. Google Sheets 최초 요청은 약 1.15~1.64초였다. 외부 서비스의 지연은 여전히 생길 수 있다.
- 기존 쌀바구니의 숨긴 탭 조회 중지·중복 요청 억제와 정적 설명 페이지의 반복 조회 방지는 회귀 테스트로 확인했다. 공지 넘김은 숨긴 탭과 열린 대화상자에서 멈추며, 홈 스쿠터는 지속적인 유휴 렌더링을 하지 않는 구조다.

## 검증과 한계

`npm test`, `npm run test:rice-basket`(138개), JS·로컬 import 검사(195개), 26개 페이지 참조 검사가 통과했다. 댓글의 가시성·동시 조회·실패 재시도·캐시 만료·최신 값 갱신, 화면별 모듈 선택, 화면 밖 3D 로딩을 회귀 검사에 추가했다.

운영 홈은 CPU 4배 감속·약 6Mbps·80ms 지연·캐시 미사용 조건에서도 표본 1회의 FCP/LCP가 약 1.62초였고, 약 79~87ms의 긴 작업 3개가 관측됐다. 저사양 기기에서 초기 처리와 3D 로딩이 부담이 될 여지가 있다. 실제 휴대폰의 FPS나 전체 사용자의 Core Web Vitals는 측정하지 않았다. 변경 후는 로컬에서 동작·요청 수를 확인했으므로 운영과 로컬의 절대 시간 차이를 개선율로 사용하지 않는다.

로그인 뒤 모든 관리·정산·PDF 전체 내보내기를 실제 데이터로 실행하지 않았다. 대용량 PDF·외부 CSV·API 첫 실행·네트워크·기기 GPU에 따른 지연 가능성은 남는다. 운영 데이터, 인증·Firebase 규칙, 외부 앱은 변경하지 않았다. 배포는 이번 성능 개선 파일로 범위를 제한하며 기존 운영의 다른 파일은 유지한다. 표본은 `.data/site-performance-2026-11-08/metrics.json`에 보관했다.
