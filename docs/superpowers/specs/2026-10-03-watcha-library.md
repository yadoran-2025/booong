# 왓챠-도서관 호환 시스템 설계 초안

책 정보 추가: 공개 책 페이지의 해당 작품 JSON-LD에서 저자·출간 정보·분류·책 소개를 ISBN과 함께 정규화한다. 카드 전체를 클릭하거나 제목 버튼을 선택하면 네이티브 dialog에서 책 정보를 먼저 보여주고, 대출 상세는 그 아래 기본 접힌 별도 영역으로 둔다. 기존 캐시는 소장·대출 결과와 수동 ISBN을 보존하며 metadata 전용 조회로 보완한다. 저장 보완은 1.5초 간격으로 진행하며, 429 응답의 대기 시간을 적용해 자동으로 이어서 처리한다. 정보가 없는 저자를 추정해 표시하지 않는다.

최종 UI: 야도란·도선생은 각각 켜고 끌 수 있는 버튼이며 동시 선택이 가능하다. 그 아래 경기도서관·선경·태장마루 버튼과 나머지 도서관 메뉴를 둔다. 도서관은 한 곳씩 선택한다. 선택한 계정의 목록을 합쳐 왓챠 작품 ID의 중복을 제거하고 선택한 지점에서 대출 가능한 책만 작은 표지 카드로 기본 표시한다. 공유 책에는 두 계정 이름을 모두 표시한다. 목록 관리에 전체 새로 불러오기·상태 재조회를 두며 수동 ISBN 교정·조회 중단 보호·완전한 계정별 캐시를 유지한다. 불확실·미소장 책은 기본 목록에서 제외되며 대출 가능 필터를 해제해 확인할 수 있다. 이 최종 요청이 아래 이전 UI 설명에 우선한다.

최신 추가 요청: 긴 카드 대신 화면 너비에 맞춰 여러 열의 작은 카드를 보여준다. 수원은 통합검색의 24개 지점을 각각 체크할 수 있고 선택 목록은 접고 펼친다. 북수원·광교홍재 등 실제 대출 가능한 도서관 이름을 카드에 표시한다. 선택한 지점 중 대출 가능 소장본이 있으면 초록, 모두 대출 불가·미소장이 확인되면 빨강, 원천 실패·미확인은 회색이다. 기존 캐시의 지점명과 새 응답의 기관 코드를 모두 지원한다. 소장본이 선택 카탈로그 밖에 있더라도 상세에서 누락시키지 않는다. 경기도서관과 용인시 전체 선택은 유지하며 용인의 실제 대출 가능 지점명도 카드에 표시한다.

최신 UI 요청: 책 카드는 작은 표지·제목·상태 중심의 컴팩트 행이다. ISBN·기관별 지점·청구기호·반납 예정일·재조회는 상세를 펼쳐 본다. 도서관 선택은 경기도서관·수원시·용인시 체크리스트로 바꾸고 브라우저에 저장한다. 초록은 선택한 기관 중 하나라도 대출 가능, 빨강은 선택한 기관 모두 대출 불가·미소장이 확인된 경우다. 불확실한 기관이 있고 대출 가능한 곳이 없으면 회색으로 표시한다. ISBN 미확인·조회 중·선택 없음도 회색이며 상태 문구로 구분한다. 도서관 선택 변경은 재조회 없이 색상을 갱신하고, 도서를 숨기는 것은 별도 대출 가능 필터가 담당한다.

작성일: 2026-10-03. 상태: 등록한 두 공개 계정의 전체 목록·브라우저 저장·수동 갱신 구현. 검증 기록은 `2026-10-03-watcha-library-sources.md`를 참조한다.

추가 요청: 루프백 로컬 개발 서버의 이 페이지는 로그인 없이 조회한다. 운영 환경 인증은 유지한다.

추가 요청: 목록 응답의 `poster.medium`(없으면 `poster.small`)을 책 표지로 표시한다. 검증한 `https://an2-img.amz.wtchn.net` 이미지 URL만 허용한다. 표지가 없거나 깨지면 표지 없음 자리를 유지하며 도서 조회는 계속한다. 네이티브 이미지 지연 로딩으로 전체 목록의 이미지 요청을 제한하고 브라우저 저장 결과에 표지 URL을 포함한다. 기존 캐시는 도서관 조회 결과·수동 교정을 유지하면서 목록 메타데이터만 추가로 모은다.

최신 사용자 지시가 아래 초기 다중 계정 설계보다 우선한다. 야도란(`WwRqoyDgkV5lz`)과 도선생(`6ewxa7ae1WvQ1`)을 고정 등록하고 선택할 수 있다. 전체 목록을 자동으로 모은 뒤 모든 책을 순차 조회한다. 목록과 결과는 브라우저 IndexedDB의 계정별 레코드에 저장하며 재방문에 재사용한다. 새로 불러오기는 현재 목록·도서관 상태를 갱신한다. 작업 중 전환·갱신은 이전 요청을 취소하고, 중단된 저장 결과의 미조회 책은 이어서 처리한다. 수동 ISBN 교정은 같은 책의 갱신에도 유지한다.

도서 상세의 교보 링크 ISBN으로 판본을 식별하며 실패 시 직접 입력한다. 도서관의 현재 공개 검색 응답을 사용하고 운영 환경 관리자 인증을 매 요청에 적용한다. 자유 계정 관리·정기 수집·서버 저장소·Firebase 변경·운영 배포는 제외한다. 제공자 동의를 확보했다고 주장하지 않으며 비공개 접근을 우회하지 않는다.

## 목적과 기본 범위

관리자 페이지의 운영 도구에 **왓챠-도서관 호환 시스템** 카드를 추가한다. 여러 왓챠피디아 계정의 **도서 ‘읽고 싶어요’ 목록**을 가져와 경기도서관·수원시 도서관·용인시 도서관의 소장 여부와 대출 가능 상태를 보여준다.

사용자는 실험용 계정 1개를 제공했고 **자동 연동을 유지하고 허용 경로 확보 후 진행**을 선택했다. 도서관 지점 범위는 추가 답변이 없으므로 아래 계획 가정을 유지한다.

- 화면에서 프로필 URL을 등록하고 조회할 계정을 선택한다. 최초 버전은 최대 10개.
- 경기도서관은 실물 도서를 소장하는 경기도서관 1개 기관이다. 경기도 전체 도서관이나 전자도서관을 뜻하지 않는다.
- 수원·용인은 해당 시의 전체 공공도서관을 기본 범위로 삼고 지점 선택을 지원한다. 작은도서관·스마트도서관·학교도서관·전자책은 최초 범위에서 제외한다.
- 운영자 개인 브라우저에 계정 URL·별칭·선택 지점·수동 ISBN 연결만 저장한다. 다른 운영자/기기에 공유하는 계정 관리 DB는 만들지 않는다.
- 수동 ‘목록 불러오기’와 ‘대출 상태 다시 확인’을 제공한다. 정기 수집·알림·예약·상호대차 신청은 제외한다.

## 확인된 코드 기반

- `js/admin.js:92-100`에서 관리자 검증 후 두 카드(방문 통계, 교과서 분석)를 렌더링한다.
- `admin.html`은 `#admin-root`를 사용하는 정적 페이지이며 `css/admin.css`의 `.admin-tool`을 재사용할 수 있다.

- 현재 `js/admin.js`는 `data-page="textbook"`만 자동 렌더링에서 제외한다. 새 페이지에서 가져올 때 홈 화면이 덮어쓰지 않도록 관리자 홈만 자동 실행하도록 범위를 좁힌다.

- 기존 Node ESM, `fetch`, `node:assert/strict`, `scripts/serve.mjs`와 검사 명령을 사용한다. React·새 테스트 프레임워크·공통 수집 플랫폼을 도입하지 않는다.

**구현 진입 조건:** 허용된 왓챠 목록 접근 경로와 세 기관의 서버 조회 계약을 검증해야 한다. 정확한 upstream 경로·파라미터·인증·분기·페이지네이션·응답 필드는 검증 보고서에 확정한다. 검증 전 임의의 비공식 API를 계획의 확정 사실로 적지 않는다.

왓챠 연동이 허용되지 않거나 서버 접근이 불가능하면 자동 연동 단계는 보류한다. 사용자에게 목록 제공/파일 가져오기 대안을 제시할 수 있지만, 사용자 동의 없이 자동 연동 요구를 파일 업로드로 바꾸거나 기능 완성으로 보고하지 않는다. 현재 상태를 조회할 수 없는 도서관은 정보나루의 전날 결과를 별도 표시할 수 있으나 ‘현재 대출 가능’으로 표시하지 않는다.

## 사용자 흐름

1. 관리자 홈에서 새 카드를 누른다. 제목은 `왓챠-도서관 호환 시스템`, 설명은 `읽고 싶은 책의 도서관 소장 여부와 대출 상태를 확인합니다.`, 링크는 `watcha-library.html`이다.
2. 프로필 URL·별칭을 등록하고 계정을 선택한다. 왓챠 계정의 비밀번호나 세션 쿠키를 받지 않는다. BOOONG 관리자 Google 로그인과 왓챠 데이터 접근 권한은 별개다.
3. ‘목록 불러오기’를 누른다. 도서 wishlist만 페이지 단위로 가져오고 전체 완료/일부 완료/실패를 계정별로 표시한다. 영화·평가한 도서·컬렉션을 섞지 않는다.
4. ISBN이 같은 판본을 합쳐 책 제목·저자·출판사·담은 계정들을 보여준다. ISBN이 없거나 잘못된 책은 `ISBN 확인 필요`로 남기고 후보 검색 또는 직접 입력으로 판본을 확정한다. 제목만 같은 책을 자동 병합하지 않는다.
5. 기본 지역은 세 그룹 모두다. 처음 20권을 조회하고 `조회 완료 n권 / 불러온 전체 m권`과 ‘다음 20권 조회’를 제공한다. 나머지는 `아직 조회 안 함`으로 표시한다. 모든 페이지·도서를 순차 조회할 수 있어야 하며 한도를 조용히 잘라내지 않는다.
6. 결과에는 지역·지점명·소장·대출상태·조회 시각·출처·데이터 기준을 표시한다. 원문에 있을 때만 자료실·청구기호·반납예정일을 표시한다. 원문 검색/상세 링크를 제공한다.
7. 계정·지역·지점·상태·제목으로 필터한다. 대출 가능 결과를 먼저 정렬한다. 미조회·ISBN 확인 필요·조회 실패 건수는 항상 별도로 남긴다. 새로고침은 원문 상태를 다시 조회한다.

## 판정과 실패 처리

- 개별 지점 상태는 `available`, `unavailable`, `not-held`, `unknown`으로 구분한다. UI 문구는 각각 `대출 가능`, `소장 · 대출 불가`, `미소장`, `확인 불가`다.
- `미소장`은 정확한 ISBN에 대한 해당 지점의 정상·완전한 조회가 명시적으로 소장 없음을 반환할 때만 사용한다. 정보나루 검색에 없거나 지원하지 않는 지점은 `확인 불가`다.
- 기관별 `coverage`는 `full`, `partial`, `unknown`; `status`는 `ok`, `partial`, `unavailable`, `unsupported`다. 전체 미소장은 선택한 모든 지점이 완전하게 확인됐을 때만 표시한다.
- `freshness`는 `current`, `previous-day`, `unknown`이다. `current`도 조회 순간의 원문 상태이며 방문 때 대출을 보장하지 않는다. 조회 시각과 원문 데이터 날짜를 분리하고, 원문 날짜가 없으면 날짜를 만들어 넣지 않는다.
- 예약·열람전용·정리중·분실·보존서고 등은 원문 사유를 남긴다. 알 수 없는 새 상태는 `unknown`; 단순히 ‘대출중이 아님’을 대출 가능으로 해석하지 않는다.
- 네트워크 오류·429·권한 오류·비공개 계정·파싱 실패·응답 형식 변경·불완전 페이지는 빈 목록이나 미소장이 아니다. 이전 화면을 남길 경우 반드시 이전 결과임을 표시한다.

## Global Constraints

- 관리자 화면과 모든 API 요청은 기존 Google 관리자 검증을 재사용한다.
- BOOONG Firebase 웹 앱은 `1:266288546185:web:727060b22ce9643d0c2158`, 프로젝트는 `yadoran-2025`; 이 기능은 기존 Authentication을 사용하며 Firebase 규칙·Functions·Hosting·다른 앱을 변경하지 않는다.
- BOOONG Design System `https://yadoran-2025.github.io/booong-design-system/releases/v2.0.0/booong.css`와 기존 토큰·컴포넌트를 사용한다. 가이드는 `https://github.com/yadoran-2025/booong-design-system/blob/main/AI_GUIDE.md`이다.
- 원문 조회는 서버에서 실행한다. 외부 API 키는 `DATA4LIBRARY_AUTH_KEY` 서버 환경변수로만 보관한다. 원문 목록·토큰·키를 정적 JSON·공개 Google Sheet·로그에 저장하지 않는다.
- 요청 프로필은 `https://pedia.watcha.com/ko/users/{id}` 또는 `https://watchapedia.com/ko/users/{id}`만 허용한다. ID는 `[A-Za-z0-9_-]{1,80}`; query·hash는 제거하고 사용자정보·다른 경로·다른 호스트·다른 포트는 거부한다.
- 서버는 고정된 검증 완료 HTTPS 호스트/경로만 호출한다. 사용자 제공 next URL을 따라가지 않으며 외부 redirect는 자동 추적하지 않는다.
- 최대 10개 계정, 외부 요청 timeout 8초, 응답 원문 최대 2 MiB, wishlist 페이지당 최대 50권, 브라우저 도서 조회 동시 2건, 서버 기관 조회 동시 3건으로 시작한다.
- 초기 결과 저장은 메모리뿐이며 영속 DB·cron·공유 캐시를 추가하지 않는다. 모든 API 응답은 `private, no-store`다.
- 브라우저 설정 키는 `booong:watcha-library:{firebaseUid}:v1`; 계정 전환 시 결과와 진행 요청을 취소하고 새 UID의 설정만 불러온다. 저장 실패는 안내하되 조회 기능을 막지 않는다.
- 외부 문자열은 `escapeHtml`/`textContent`로 렌더링하고 원문 링크의 protocol·hostname을 검증한다. 표지·긴 소개문 수집은 최초 범위에서 제외한다.
- 계획 단계에서는 문서만 작성한다. 실행 전 사용자에게 계획 검토와 실행 방식 선택을 요청한다.

## 완료 기준

새 관리자 카드로 진입해서 두 개 이상의 허용된 계정 wishlist를 끝까지 읽을 수 있고, 같은 판본을 합친 뒤 선택한 도서관들의 결과와 최신성·부분 실패를 구분한다. 세 지역 모두 현재 상태를 조회하는 실환경 검증이 필요하다. 실패/미지원 기관은 감추지 않는다. 현재 상태 조회나 자동 wishlist가 불가능한 채로 남아 있으면 부분 구현으로 보고하고 전체 목표 달성으로 표시하지 않는다.
